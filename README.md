# GrowWise — เติบโตอย่างเข้าใจ ในทุกก้าว

แพลตฟอร์มคัดกรองและติดตามพัฒนาการเด็กสำหรับผู้ปกครอง ครู และผู้เชี่ยวชาญ

---

## 1. ภาพรวมสถาปัตยกรรม (System Architecture)

แพลตฟอร์มประกอบด้วย 2 เว็บแอปพลิเคชันที่ **แยก URL กันชัดเจน** แต่ใช้ฐานข้อมูลและโมเดลข้อมูลชุดเดียวกัน:

1. **GrowWise User Web App (พอร์ต 3000):**
   - ออกแบบแบบ **Desktop First** สำหรับผู้ปกครองและคุณครู (เปิดผ่านคอมพิวเตอร์เป็นหลัก พร้อม responsive สำหรับแท็บเล็ตและมือถือ)
   - แบรนด์: ม่วงเข้ม `#6950A1`, ม่วงอ่อน `#8672B2`, ฟอนต์ **Noto Sans Thai**
   - เมนู: หน้าแรก / เด็กของฉัน / แบบประเมิน / ประวัติ / บัญชีผู้ใช้
   - ฟังก์ชัน: คำนวณอายุ ณ วันที่ประเมินอัตโนมัติ, การจัดการความยินยอม PDPA, การผูกสิทธิ์ครู, การทำแบบประเมินพร้อม Progress Bar และการบันทึกร่าง

2. **GrowWise Admin (พอร์ต 3001):**
   - ออกแบบแนว **Medical Analytics Dashboard** สำหรับ Super Admin, แอดมิน และผู้เชี่ยวชาญ
   - เมนู: Dashboard สถิติ, จัดการแบบประเมินและเวอร์ชัน (Draft → Review → Published → Archived), ตัวสร้างแบบประเมิน (Builder), เกณฑ์และการคำนวณ (Test Bench), ตารางผลประเมินทั้งหมด, จัดการผู้ใช้และสิทธิ์ (RBAC), บันทึกความปลอดภัย (Audit Logs)

## 2. เครื่องมือประเมิน KUS-SI 5 ชุด (อ้างอิงโรงพยาบาลราชานุกูล)

ระบบได้นำเข้าโครงสร้างแบบคัดกรอง KUS-SI ครบถ้วนทั้ง 5 ชุด (แทนที่ SNAP-IV เดิมทั้งหมด):

1. **KUS-SI 1:** แบบประเมินพฤติกรรมสมาธิสั้น (ADHD) รวม 30 ข้อ (ซน/วู่วาม 15 ข้อ + ขาดสมาธิ 15 ข้อ)
2. **KUS-SI 2:** แบบประเมินภาวะบกพร่องทางการเรียนรู้ ด้านการอ่าน (LD Reading) 20 ข้อ
3. **KUS-SI 3:** แบบประเมินภาวะบกพร่องทางการเรียนรู้ ด้านการเขียน (LD Writing) 20 ข้อ
4. **KUS-SI 4:** แบบประเมินภาวะบกพร่องทางการเรียนรู้ ด้านการคิดคำนวณ (LD Math) 20 ข้อ
5. **KUS-SI 5:** แบบประเมินกลุ่มอาการออทิซึม (Autism / PDDs) 40 ข้อ (สังคม, การสื่อสาร, พฤติกรรมซ้ำๆ)

### มาตรการความปลอดภัยทางคลินิก (Clinical Guardrails)
- **ห้ามเดาเกณฑ์ T-Score:** เนื่องจากในเอกสารอ้างอิงมีเฉพาะเกณฑ์ T-Score แต่ไม่มีตารางแปลงคะแนนดิบมาตรฐาน ระบบจึงคำนวณเฉพาะคะแนนดิบรวมและรายด้าน พร้อมแสดงสถานะ **“รอผู้เชี่ยวชาญตรวจและแปลผล”**
- **ป้ายกำกับบังคับ:** ทุกหน้าผลรายงานและสรุปจะแสดงข้อความเด่นชัด: **“ผลนี้เป็นการคัดกรองเบื้องต้น ไม่ใช่การวินิจฉัย”**
- **ป้ายกำกับตัวอย่าง:** แสดงป้าย **“ตัวอย่างสำหรับทดสอบระบบ”** ในข้อมูลที่รอการอนุมัติทางวิชาการ
- **การจำกัดสิทธิ์ผู้ประเมิน:** KUS-SI เป็นการสังเกตพฤติกรรมในโรงเรียน ระบบกำหนดให้ **คุณครู (Teacher)** เป็นผู้ประเมินหลัก ผู้ปกครองไม่สามารถตอบแทนครูได้โดยอัตโนมัติ

## 3. Data Abstraction Layer & Backend Selection

ระบบใช้ **Repository Pattern (`IDataAdapter`)** เพื่อแยก UI ออกจาก Database:
- **โหมด Prototype ปัจจุบัน:** ใช้ `MockDataStore` ที่สมบูรณ์แบบ มีบัญชีผู้ใช้ครบ 5 บทบาท, เด็กตัวอย่าง, ประวัติ และ Audit trail รันได้ทันทีโดยไม่ต้องต่อฐานข้อมูลภายนอก
- **การเชื่อมต่อ Supabase:** เตรียมไฟล์ `packages/shared/supabase_schema.sql` พร้อม Row Level Security (RLS) และ Security Definer functions
- **การเชื่อมต่อ Firebase:** เตรียมไฟล์ `packages/shared/firebase_rules.json` พร้อม Security Rules ที่ปฏิเสธโดยค่าเริ่มต้น

## 5. วิธีติดตั้งและเปิดใช้งาน (Getting Started)

### การรันเซิร์ฟเวอร์แบบ Dual-Port (User App 3000 + Admin App 3001)
```bash
node server.js
```
ระบบจะเปิดให้บริการ 2 พอร์ตพร้อมกัน:
- **GrowWise User Web App:** `http://localhost:3000`
- **GrowWise Admin Web App:** `http://localhost:3001`

### การทดสอบระบบ (Automated Test Suite)
```bash
node tests/test-suite.js
```

## 6. แนวทางการ Deploy บน Vercel

### ตัวเลือกที่ 1: Deploy แยก 2 โปรเจกต์ Vercel (แนะนำสำหรับ URL แยกสมบูรณ์)
- **โปรเจกต์ 1 (User App):** Root directory ตั้งเป็น `apps/user-web` ผูกโดเมน `user.growwise.app`
- **โปรเจกต์ 2 (Admin App):** Root directory ตั้งเป็น `apps/admin-web` ผูกโดเมน `admin.growwise.app`
- ทั้งสองโปรเจกต์ต่อ Database ชุดเดียวกันผ่าน Environment Variables ใน Vercel Dashboard

### ตัวเลือกที่ 2: Deploy รวมผ่าน `vercel.json` (Unified Rewrites)
- ใช้ `vercel.json` ที่แนบมาในโปรเจกต์ ซึ่งจะ rewrite `/admin` ไปยัง Admin App และ path ปกติไปยัง User App
